# LLM routing, the spend cap, and the Codex fallback

Which provider and model every call uses and how it is paid for. **The Claude API is the default** (`EDWARD_LLM_PROVIDER` unset or `anthropic`, read per call; set `ANTHROPIC_API_KEY`): every builder returns `ChatClaude` with a per-purpose model from one table ([Claude](#claude-the-default-provider)), every call is priced in dollars, and a daily spend cap ($5 by default) keeps Edward's own work from running away ([the spend ledger and the cap](#pay-per-token-the-claude-spend-ledger-and-the-daily-cap)). **Codex is an unofficial, opt-in fallback** (`EDWARD_LLM_PROVIDER=codex`): GPT through the ChatGPT subscription's private Codex backend with the Codex CLI's login — it may break at any time and may conflict with OpenAI's terms; the later sections describe it (the model catalog and its knobs, the weekly quota meter, the rate gate, Codex OAuth, the prompt-cache fingerprint and the spend ledger that says who spent the week). The surplus queue that spent a spare Codex week is retired ([surplus.md](surplus.md)).

**Every runtime LLM call goes through the `llm_utils.py` builders** (`build_chat_llm`, `build_background_llm`). One adapter speaks to Anthropic: `ChatClaude` uses the `anthropic` SDK itself (it prices and caps every request), so nothing in the runtime imports `langchain_anthropic` (`tests/test_no_anthropic_runtime.py`). Every call is labelled with a purpose (`mind:<reason>`, `pulse`, `ping:owner` / `ping:friend`, `turn:<source>` — [below](#the-codex-spend-ledger--who-spends-the-codex-week)), which both spend ledgers read. **A user-facing call at background priority is a bug.**

## Claude: the default provider

(`services/claude_chat_model.py`, `claude_routing.py`, `llm_errors.py`; 2026-10-10.) With the provider `anthropic` — the default, also when the variable is unset; an unknown value stays on anthropic with one warning (`claude_routing.llm_provider`) — every builder in `llm_utils.py` returns `ChatClaude`, a LangChain chat model over the Anthropic Messages API (the `anthropic` SDK directly, raw SSE through `messages.with_streaming_response`), and `ANTHROPIC_API_KEY` is read from the environment. `settings.model` defaults to `claude-sonnet-5-5` and `settings.provider` to `anthropic`; the default persona is generic and names the owner through the `{OWNER}` token.

- **One table, per purpose** (`claude_routing.DEFAULT_ROUTES`; [where it came from](#where-the-routes-came-from)):

  | purpose | model, effort | cache | who rides it |
  |---|---|---|---|
  | `chat` | `claude-sonnet-5-5`, medium | 5m | every chat-path turn not named below: the owner's chat, **ping replies** (`ping`, `ping_owner`), scheduled events, heartbeat replies, workers |
  | `mind` | `claude-sonnet-5-5`, medium | 5m | every wake: follow-through, the speaker (`EDWARD_SPEAK_MODEL` when set), the nightly, free time |
  | `pulse` | `claude-sonnet-5-5`, medium | 5m | the surfaces pulse |
  | `background` | `claude-haiku-5-5`, high | 5m | every `build_background_llm` caller: extraction, entities, consolidation, the noticer (`EDWARD_NOTICE_MODEL` when set), photo descriptions (there is no media route), tags |
  | `voice` | `claude-sonnet-5-5`, low | 1h | spoken turns |
  | `judge` | `claude-opus-5-5`, high | 5m | `build_background_llm(route="judge")` |

  Each row: `EDWARD_CLAUDE_<PURPOSE>_MODEL` / `_EFFORT` / `_MAX_TOKENS` / `_THINKING_DISPLAY` / `_CACHE_TTL`, read per call; a bad override is ignored with one WARNING. The turn's purpose comes from `turn_source` (voice — `voice` or the hub's `hub_voice`, `claude_routing.VOICE_TURN_SOURCES` —, mind, pulse, else chat). **Never run an agentic route at Sonnet low** (the weakest agent tested). If the judgement check fails on Sonnet, `EDWARD_CLAUDE_MIND_MODEL=claude-opus-5-5` with `EDWARD_CLAUDE_MIND_EFFORT=low` is the measured fallback (about +$0.72 a day at the original install's volume). Tests: `tests/test_claude_routing.py::TestTheBenchmarkRoutes`.
- **Model ids are fixed strings**, never catalog lookups. `llm_utils.turn_model_for` maps a turn's model before the ledger and the build: a Codex id (old settings, a stale checkpoint) or a retired Claude id becomes the purpose's model; only a current id (`KNOWN_CLAUDE_MODELS` or one a route is configured with) passes. `provider_for` answers `anthropic` for everything while the provider is anthropic (the built model is Claude whatever the id); `mind_model_for`, `pulse_model_for`, `background_model` and `voice_model` answer from the table; `GET /api/settings/models` reports the table with `provider: "anthropic"` (`mind_service.routing_summary`).
- **What does not apply on Claude**: the Codex catalog, the Codex meter and its pacing (`ChatClaude` asks the daily spend cap instead — [below](#pay-per-token-the-claude-spend-ledger-and-the-daily-cap)), `EDWARD_CHAT_REASONING_EFFORT`, the mind's per-reason efforts and the spare-quota raise — the table's effort is what is sent. **The Codex meter gates nothing** (`expression_service.codex_meter_governs`): `quota_state()` and `GET /api/mind/now` read the day's spend cap instead, so a spent Codex week — which no Claude call refreshes — never skips a wake or the pulse and never shows him resting; before this fix (2026-10-11) a spent window kept the mind asleep until its own reset, up to seven days. Startup skips the Codex meter restore and fetch unless the provider is codex. **The surplus queue is retired**: it existed to spend a prepaid week, and on a pay-per-token API that is money; the spend gate refuses every `surplus` call.
- **Max tokens** cover thinking and the reply (thinking counts against them): 32K chat and mind, 16K pulse, background and judge, 8K voice. A caller's larger value is kept; a smaller one is not — Codex never sent one, so the 100–4,096 values in the enrichment callers were reply sizes.
- **The request**: adaptive thinking (Opus 5.5 cannot turn it off) with `display: "summarized"` (`omitted` for background and judge) and `block_binding.prefix_mismatch_behavior: "drop_block"` under beta `thinking-binding-controls-2026-08-01`; `output_config.effort`; never `temperature` / `top_p` / an assistant prefill; tools sorted by name; `tool_choice` `auto` — the adapter's default is one call per response (`disable_parallel_tool_use`) unless the binder asks for parallel calls, as the tool loop does ([tool-loop.md](tool-loop.md)); a forced choice becomes `auto` on Opus and Sonnet 5.5 (they 400 on it; logged once), `none` is kept; `fallbacks: "default"` with beta `server-side-fallback-2026-07-01` on Opus and Sonnet 5.5 only (Haiku 5.5 has no server-side fallback).
- **The prompt cache**: on a Claude turn `compose_system_prompt(dynamic_split=STATIC_DYNAMIC_SPLIT)` marks where the static part (base, tool manual, directives) ends. The static text is one top-level system block cached at the route's TTL (5 minutes on every route but voice — turns hours apart rarely read a 1-hour write back); the per-turn text (memories, briefings, time, the entry prompt, a closing instruction) is a mid-conversation `{"role": "system"}` message right after the last human message (a second, uncached system block on a model without them; a model that 400s on them is learned and retried that way). The owner's last message carries a 5-minute breakpoint and top-level automatic caching covers the growing tail, so history up to their last message is read back on the next turn. A smoke run read 2,910 of 2,912 input tokens from cache on a repeated request.
- **Replay and checkpoints**: raw blocks ride `AIMessage.additional_kwargs["claude_content"]` and are replayed verbatim within the turn (thinking signatures included; after a server-side fallback only the continuation and paired server blocks); older turns are rebuilt from text and tool calls; `strip_claude_thinking` drops the blocks from older turns before checkpointing ([tool-loop.md](tool-loop.md)).
- **The stream**: raw SSE bytes are split on CR, LF and CRLF only, then decoded (`_byte_lines`, 2026-10-11). httpx's `aiter_lines` also splits on U+2028, U+2029 and U+0085, which JSON carries unescaped inside a string, and the cut `data:` line was dropped silently — a piece of the answer, a tool's arguments, a thinking block. The fake client in the tests serves a real `httpx.Response` over raw UTF-8 in small chunks.
- **Stops and errors**: `refusal` is `REFUSAL_NOTE`, never an exception or a tool call; `max_tokens` returns the partial answer (`incomplete_reason`) with no tool calls; `pause_turn` is resumed up to three times. Every failure is one `LLMProviderError` (a `ValueError`) whose `retryable` covers overloaded, 5xx, 429, 408/409 and dropped connections, not a 400 or a 401; `mind_service.is_transient_error` reads it first. The SDK retries HTTP errors twice; the adapter retries a transient failure once more while nothing has reached the consumer. `LLMCallTimeout` still bounds every call; `CLAUDE_REQUEST_TIMEOUT_SECONDS` (300) bounds a whole request.
- **Spend** (wired 2026-10-11 — until a review that day the adapter never asked the cap and wrote `codex_calls` rows, so `llm_calls` stayed empty and the cap read $0.00 all day): before **every** HTTP request — the first, each `pause_turn` continuation and the one retry — `ChatClaude._admit` asks the daily spend cap (the gate's `acquire_spend` for the first, which keeps background's stampede spacing; `llm_spend.check_spend` for the rest), outside the code that records the request, so a refused call sends and records nothing. This holds whatever `EDWARD_LLM_PROVIDER` says: a `ChatClaude` built by hand is still paid per token. After each request, success or failure, one `llm_calls` row priced on that request's own `usage` (`llm_spend.record_claude_call`; never `codex_calls`, so the Codex burn views stay Codex) and one `[claude-cache]` line — uncached/read/write/output tokens, the request's cost and short hashes of the system prompt and tools. The response's `estimated_cost_usd` is the sum of its requests' prices, never the price of `_sum_usage`'s total (which adds the requests' prompts together — two 60K Haiku prompts would price at the >100K card). Prices live only in `llm_pricing.py`. **A server-side fallback**: top-level `usage` covers only the attempt that produced the message, so the counts are the sum of `usage.iterations` (`billed_usage` for the line and `usage_metadata`; `llm_pricing.price` sums them for the row; a mid-stream decline bills at normal rates) and each attempt is priced at the model that ran it — its own `model` when an iteration names one, else the requested model before the first `fallback_message` and the served one (`message_start.message.model`) from there on. The `llm_calls` row (`model` is the served model: `record_claude_call(..., served_model=…)`), the line (`requested=` names the model asked for) and `response_metadata` (`requested_model`) say which model served it. A sticky fallback with no iterations is priced at the served model.
- **Live check**: `backend/scripts/claude_smoke.py` (not a test; a few cents) sends a tool request to Haiku 5.5 and Opus 5.5, repeats it for the cache read, and streams the tool round back with its thinking replayed; `--effort high --question …` makes the model think first. Tests: `tests/test_claude_chat_model.py` (the byte-split stream, fallback billing), `tests/test_claude_routing.py` (the Codex meter on Claude, the conftest pins), `tests/test_claude_spend_wiring.py` (the cap and the ledger through the adapter; a fake `AsyncAnthropic` in `tests/fixtures/fake_anthropic.py`).

## Pay per token: the Claude spend ledger and the daily cap

(`services/llm_spend.py`, `services/llm_pricing.py`, table `llm_calls`; 2026-10-10)
- **Why**: on the Claude API every token is paid for, and nothing expires at a reset — there is no weekly window to pace against and nothing spare to spend. A dollar ledger and a hard daily cap take the Codex meter's role.
- **Pricing** (`llm_pricing.price(model, usage, served_model=…)`, pure, never raises; the only price table — `claude_chat_model.estimate_cost_usd` delegates to it): USD per MTok — `claude-opus-5-5` $4 in / $20 out, cache read $0.20, 5-minute write $5, 1-hour write $8; `claude-sonnet-5-5` $2 / $10, $0.20, $2.50, $4; `claude-haiku-5-5` $0.10 / $0.50, $0.01, $0.125, $0.20, and for a prompt over 100K tokens (uncached + cache read + cache write) $0.50 / $2.50, $0.05, $0.625, $1. Web search $10 per 1,000. `input_tokens` is the uncached remainder; `cache_creation` splits writes by TTL (an unsplit remainder is the default 5 minutes); `output_tokens` includes thinking; `usage.iterations` is summed, each attempt at the rates of the model that ran it. Every id an `EDWARD_CLAUDE_<PURPOSE>_MODEL` override could name has its list price — the fallback targets and the older Opus, Sonnet, Haiku, Fable and Mythos ids, with the 1M-context premium past 200K tokens where it applies. **An unknown version is priced at its family's dearest rates** (each rate the highest any member charges, at every prompt size) and an unknown family at the dearest of all — never free, never under a listed member: the cap must over-count rather than under-count (`test_llm_pricing.py` pins the floor).
- **The ledger**: `llm_calls`, one row per call — provider, model, purpose, priority, uncached input / cache read / cache write / output / thinking tokens, web searches, `cost_usd`, latency, first token, ok, error, conversation, the turn's source and id; `created_at` stamped in UTC by Python. The purpose label is read the way the Codex ledger reads it (`call_purpose.current_purpose()` first, then the model's `purpose`, then the stack walk; the turn from `turn_ledger.current_turn()`), so `mind:<reason>`, `pulse`, `turn:<source>` carry over. Kept `llm_spend.RETENTION_DAYS` (400) by `turn_ledger.prune` — the credits view is a sum since the purchase. Writes are fire-and-forget (`llm_spend.WRITES_ENABLED`, off in unit tests).
- **The adapter** (`ChatClaude`, [above](#claude-the-default-provider)): before every request `_admit` — `await get_llm_rate_gate().acquire_spend(priority, purpose=…)` for the first (what `acquire` delegates to under the anthropic provider), `llm_spend.check_spend(priority, purpose=…)` for continuations and the retry. After each request, success or failure, `llm_spend.record_claude_call(model, usage, purpose=…, priority=…, latency_ms=…, ttft_ms=…, ok=…, error=…, conversation_id=…, served_model=response.model)` — synchronous, never raises, returns the cost.
- **The cap** — `EDWARD_DAILY_SPEND_CAP_USD` (5; design decision of 2026-10-11 — it was 10), `EDWARD_BACKGROUND_SPEND_SHARE` (0.6), `EDWARD_INTERACTIVE_RESERVE_USD` (3), over the owner's local day (`timezone_utils.get_user_tz()`, i.e. `settings.timezone`):
  - `background` stops at cap × share and raises `LLMRateLimitDeferred` (the class the background loops already absorb);
  - Edward's own turns (`mind:*`, `pulse`, a turn whose source is the mind or the pulse — `spend_report_service.is_autonomous_call` — or anything inside `llm_spend.own_work_scope()`) stop at the cap;
  - the owner's turns, the greeting and triage run on into the reserve and stop past cap + reserve with `llm_spend.LLMSpendCapReached`, whose message is a sentence in Edward's voice. The chat path shows that sentence as it is (`routers/chat._format_chat_error_explanation`) — an explainer call would be refused by the same cap;
  - **the owner's own learning runs on their limit**: background work inside their own turn (`OWNER_TURN_SOURCES` — chat, voice, widget, Alexa, their self-chat ping, and `owner_ping`, their own `@Edward` text read after a ping; the turn record its tasks inherit) — the extraction of what they just said, the retrieval for their answer — stops past cap + reserve, not at the background line; a refused extraction is dropped, not queued, so before this a standing instruction given at 8 pm was never stored. A wake's scope or the own-work scope still wins over a turn source;
  - **an event the owner did not make is Edward's own work**: `scheduled_events_service.create_event` stamps `event_metadata.created_in` with the making turn's source, `event_is_owners` says whose it is, and the scheduler runs any other ordinary event inside `own_work_scope()` — so the mind's follow-ups stop at the cap instead of spending the owner's reserve ([scheduler.md](scheduler.md));
  - **friends' pings and the household hub's voice are Edward's own share too**: whoever is at the hub panel is not necessarily the owner, so `voice_ws` starts each hub turn inside `own_work_scope()`, like a friend's ping — it stops at the cap, a handed-off continuation included, at interactive priority ([voice.md](voice.md));
  - `surplus` is always deferred. A refusal logs `CLAUDE_SPEND_CAP` (WARNING, once a minute per code) and a background deferral writes the usual `rate_gate` / `deferred` ledger row.
- **The day's total costs nothing per call**: it is cached for `CACHE_TTL_SECONDS` (30) and bumped by every call this process records; a stale or cold cache re-reads the table (after letting this process's pending writes land), so the stop holds across a restart and sees what other processes spent. **Near a limit the cache is not trusted**: within `NEAR_LIMIT_USD` ($0.50) of the limit that decides a call, a reading older than `NEAR_LIMIT_MAX_AGE_SECONDS` (2) is re-read before the call is admitted, so the backend and the graph worker do not each admit calls against a 30-second-old total. The cap is still checked before a request, never during one: the day can end one request over it. A row that never lands (writes off, no loop, a failed insert) is kept against its day and added back on every re-read. An unreadable table fails **open** with a `CLAUDE_SPEND` WARNING — the owner must be answered.
- **The gate** (`llm_rate_gate.LLMRateGate`, one switch, no call sites changed): under the anthropic provider `acquire` delegates to `check_spend` (background keeps its 5 s stampede spacing; no Codex cooldown or meter refresh), `meter` reads None (the Codex week is not his quota — the reading is kept in `_meter`), `background_decision()` and `status()` follow the cached spend, `surplus_decision()` refuses with code `pay_per_token`. The pulse's and the mind's quota word (`expression_service.quota_state`) is `paced` once background work stopped and `exhausted` once Edward's own turns did, so wakes skip cleanly at the cap instead of failing; the skipped wake's note is "today's Claude spend cap reached" (`llm_spend.QUOTA_SKIP_NOTE`). `GET /api/mind/now`'s `quota` follows the same day (`llm_spend.quota_now` — `gate.meter` is None here, so it once read `exhausted: false` while every wake was skipped): `exhausted` at the cap, `used_percent` of the cap, `resets_at` the owner's next local midnight, `period: "day"` (`"week"` on Codex), and the presence, the presence sheet, the screen, the mind log and the Edward tab say "today's budget" for it.
- **Credits** (optional): only when `EDWARD_CREDITS_START_USD` and `EDWARD_CREDITS_START_DATE` (a local `YYYY-MM-DD`) are **both** set (`llm_spend.credits_tracked`): remaining = start − spend since that local midnight; `days_left` at the trailing three days' burn (never reaching back past the start, at least a day long). Unset, every payload says the credits are not tracked (`CREDITS_UNTRACKED_NOTE`). There is no API to read the real Anthropic balance with an ordinary key: every payload says "tracked locally; check console.anthropic.com for the authoritative balance". When you top up, set both variables again.
- **Surfaces**: `GET /api/health/spend` → `claude` (today by purpose and by model, the cap, share and reserve, remaining today, `state` ok / background_paused / own_work_paused / stopped, credits, a per-local-day series as long as `days`); `GET /api/health/report` → `spend.claude` (the headline numbers, top purposes, and `warning` once today passes 80 % of the cap); `GET /api/settings/codex-usage` → `provider` and `claude` — under anthropic it fetches no Codex meter, the windows are empty and `surplus.state` is `off`. The Fuel card (`lib/codexUsage.ts::describeClaudeFuel`) then reads "Spent today $X of $Y" (plus "credits left ~$Z (~N days)" when tracked), the bar against the day's cap with the background stop as its tick, who spent today in dollars, and — under "How this works" — that what the owner tells Edward is still remembered past the background line.
- Tests: `tests/test_llm_pricing.py`, `test_llm_spend.py` (thresholds, the owner's own learning, the own-work scope, the local day, the cache, restart persistence, credits, prune), `test_llm_spend_gate.py` (the gate, surplus, the quota word, `/api/mind/now`), `test_llm_spend_events.py` (whose event it is), `test_llm_spend_surfaces.py` (payloads, the chat sentence), `test_claude_spend_wiring.py` (the adapter end to end); frontend `__tests__/codexUsage.test.ts`, `fuelCard.test.tsx`, and the "today's budget" copy in `edwardMood`, `mindLog`, `mindNowApi`, `presenceSheetModel`, `screenPresence`, `edwardHome`.

## Where the routes came from

The route table is the outcome of a model benchmark run on the original install on 2026-10-11, against production-derived items and production volumes (the benchmark tooling is not part of this release; the code still calls the table "the benchmark's set R"). What it found, and why each row is what it is:
- **Sonnet 5.5 at medium** tied Opus 5.5 at medium on ping turns (judge mean 0.92 against 0.94; 2 wins, 10 ties, 4 losses) at 46 % of the cost and 2.3× the speed — so chat, the mind and the pulse run on it.
- **Haiku 5.5 at high** beat Sonnet at low on extraction, entities and consolidation, and as the noticer caught 4 of 4 must-notice cases with no false noticing (Sonnet at low caught 2 of 4) — so the background route runs on it.
- **Voice**: with thinking on, every model's first spoken word took 2.5–3.9 s; Sonnet at low is the fastest acceptable, and voice is the one route where a 1-hour cache pays (turns come in bursts).
- **Cache TTL per route**: a 1-hour write costs 1.6× a 5-minute one and pays only when turns reusing the prefix come within the hour; ping and speak turns hours apart paid it for nothing.
- At the original install's volume the table cost about $2.31 a day (an Opus-for-everything guess was about $2.91). Your volume will differ; the Fuel card and `GET /api/health/spend` show what you actually spend.
- Because the agentic route is not Opus, **run the judgement check and the ping eval before trusting an unattended mind on a changed route** ([testing.md](testing.md)). Still unmeasured there: the pulse on Haiku and a media route (Sonnet at low read screenshots better than Haiku, 0.93 against 0.86).

## The Codex fallback (`EDWARD_LLM_PROVIDER=codex`)

(`backend/services/llm_utils.py`, `model_catalog.py`, `codex_chat_model.py`.) With `EDWARD_LLM_PROVIDER=codex` (or `openai` / `gpt`) the builders return GPT through Codex OAuth (`ChatCodexResponses` → `chatgpt.com/backend-api/codex/responses`); with `OPENAI_API_KEY` set the auth manager uses the public OpenAI API key instead. Everything in this section applies only then.

- **Three knobs, one catalog.** `settings.model` (chat, heartbeat replies, scheduler, expression pulse, orchestrator default, Codex CLI `-m`; `llm_utils.CODEX_CHAT_MODEL` is the catalog's preferred id), `EDWARD_BACKGROUND_MODEL` (enrichment: extraction, reflection, consolidation, dreams; default `gpt-5.6-terra`, read per call), `EDWARD_VOICE_MODEL` (spoken turns, default `gpt-5.6-luna`). `EDWARD_CHAT_REASONING_EFFORT` raises `reasoning.effort` for every turn built by `build_chat_llm` — chat, wakes, pulse, heartbeat — except a spoken one; unset means the catalog default. All three resolve through `services/model_catalog.py`, which reads the Codex CLI's `~/.codex/models_cache.json` (mtime-aware; a static fallback when unreadable). `GET /api/settings/models` offers exactly the listed catalog; `POST /api/settings` refuses an id the live catalog does not serve (400 naming the catalog); a stale id in a checkpoint is rewritten to the recommended model with one WARNING per id, never a 400 per turn (on the original install a retired model failed every turn until found, and checkpointed model ids had beaten live settings on 724 threads — live settings now win). `build_background_llm(vision=True)` guarantees a model that accepts images. `reasoning.effort` comes from the catalog per model (`EDWARD_BACKGROUND_REASONING_EFFORT` overrides for enrichment; unsupported values fall back to the model default). `temperature` is a no-op on the Codex path; `max_output_tokens` is not supported by the endpoint. Tool schemas are sanitized for the endpoint (`codex_chat_model._sanitize_schema`): local `$ref`s are inlined before `$defs` is dropped (`plan(items: List[PlanItem])` once reached Codex as a dangling `#/$defs/PlanItem`; a recursive or unresolvable reference becomes a plain object), and `tests/test_codex_schema_request.py` pins that the toolset converts with no `$ref`.
- **Routing knobs** (`llm_utils`; wired in `mind_service.route_for_wake`): `EDWARD_MIND_MODEL` (default `settings.model`), `EDWARD_MIND_REASONING_EFFORT` (default `high`), `EDWARD_MIND_EFFORT_MAP` (`mention=medium,*=…`), `EDWARD_PULSE_MODEL` (default `gpt-5.6-terra` when listed), `EDWARD_PULSE_REASONING_EFFORT` (default `low`). `build_chat_llm(reasoning_effort=, turn_source=)` — explicit wins, a spoken turn (`voice` or the hub's `hub_voice`) is exempt from `EDWARD_CHAT_REASONING_EFFORT`; `build_background_llm(effort=)`. Entity extraction has its own `EDWARD_ENTITY_MODEL` (default Luna, `low` effort; [memory.md](memory.md)). `GET /api/settings/models` reports what each kind of turn runs on, resolved the way the turn resolves it (`mind_service.routing_summary`). `llm_utils.effort_with_headroom` (raise a wake's effort while the week had spare quota) went with the surplus queue and is no longer called. Tests: `test_llm_routing_knobs.py`, `test_settings_models_routing.py`, `test_mind_routing.py`.

## The quota meter and the rate gate

(`llm_rate_gate.py`, `codex_usage_service.py`, `llm_limit_alert.py`.)
- **The quota meter is real** (2026-09-11). Every Codex response carries `x-codex-primary-used-percent`, `-window-minutes`, `-reset-after-seconds` (and `secondary`), and `GET /backend-api/wham/usage` returns the same. The cap is **per account, shared by every GPT model** — on the original install three models all answered the weekly 429 at once; switching models cannot escape it. The meter reads in **whole percent**, which matters for any rate computed from it ([surplus.md](surplus.md)).
- **Rate gate**: reads the meter from every response, persists it (`llm_rate_gate_state.meter_json`), refreshes a stale sample (>15 min) from `wham/usage`. `background` calls run while every window is under a pace line (`BACKGROUND_HEADSTART_PERCENT` 15 + the elapsed fraction of the window) and under `BACKGROUND_CEILING_PERCENT` 90; otherwise they raise `LLMRateLimitDeferred` (a `ValueError` the loops absorb and retry next run). `triage` and `interactive` are never deferred: they wait ≤5 s through a 429 cooldown and go. A 429 opens a cooldown (≤1 h) and marks the meter exhausted until the reset it names; any 200 clears the cooldown. `gate.meter` is a property (a `gate.meter()` call once raised, was swallowed, and made the mind's exhausted/paced checks always "ok"). **The old budget pacer is gone** — it guessed a per-4h call budget, took the weekly cap's 429 as a 4h ceiling of ~40 calls, persisted it, and deferred every background call (image descriptions, dreams, search tags) for two days with zero real 429s in the log. Diagnostic tell: `grep "HTTP 429"` in the backend log (real) vs `LLMRateLimitDeferred` (gate); if only the latter is recent, check `GET /api/settings/codex-usage` — it shows the meter and `background_reason`.
- **Priorities that matter**: `describe_image(path, priority=...)` — the listener describing an arriving photo is background; `look` and other user-facing reads pass `interactive`; the greeting and the chat error explainer run at `triage`. A user-facing call at background priority is a bug ("Could not read image … background LLM call deferred").
- **Alerts**: every 429 / cap logs `CODEX_LIMIT` (WARNING) and pushes the owner at most once per quiet hour (`llm_limit_alert.py`; a push per 429 would train them to ignore it). A 429 whose reset is beyond 6 h is the weekly cap: reported as `usage_limit_reached`, the text says switching models will not help and when it resets, with the meter's used-percent.
- Surfaces: `GET /api/settings/codex-usage` (meter, pace decision, plan, `provider`, `claude`) → `CodexUsageCard` ("Fuel") in the Work room (pure `lib/codexUsage.ts`). Tests: `tests/test_model_catalog.py`, `test_llm_rate_gate*.py`, `test_codex_model_switching.py`, `test_codex_usage_meter.py`, `test_codex_auth_refresh_writeback.py`, `test_llm_priority_and_retry.py`; frontend `__tests__/codexUsage.test.ts`, `fuelCard.test.tsx`.

## Codex OAuth

(`codex_auth_service.py`.)
- `codex_auth_service.py` reads `OPENAI_API_KEY` if set, else the Codex CLI login in `~/.codex/auth.json` (`CODEX_AUTH_PATH` overrides; tests point it at a throwaway file). It refreshes with the Codex CLI's own OAuth client id and writes the rotated tokens back to `~/.codex/auth.json` atomically so `codex exec` keeps working. Every caller uses `get_api_key()`.
- **There is no proactive refresh** (2026-09-27): access tokens last ~8 days, and an expired one costs one refused request, which the refresh-on-401 path answers with a single refresh. The JWT-`exp` refresh had no callers and was deleted rather than wired into `codex_usage_service`, whose tests reach the real auth singleton — a refresh there would rotate the token pair `codex exec` uses, from a test run.
- **Refresh is single-flight** (2026-09-25: 29 refreshes in one outage hour, two in the same second, racing for a rotating refresh token and `auth.json`): `force_refresh` → `_refresh_once` queues on one lock, a caller that waited shares the refresh it waited behind, and a success under 60 s old (`REFRESH_REUSE_SECONDS`) is reused without a POST. A 401 that survives `ChatCodexResponses`' own refresh-and-retry raises `CodexAuthError` (a `ValueError`, `refresh_attempted=True`), and the tool loop does not refresh again — it used to stack up to four requests and three refreshes per call; a raw 401 on the `OPENAI_API_KEY` path still gets one refresh.
- **"Incorrect API key provided" after a fresh refresh is a service-side fault** (`is_service_side_auth_fault` → `CodexAuthError(transient=True)`; Codex answered it for good tokens for an hour on 2026-09-25), and its message says so instead of sending the owner to `codex login`; a shared refresh that hands back the very token just refused is not retried.
- Tests: `test_codex_auth_401.py`, `test_codex_auth_single_flight.py`.

## The prompt cache on Codex

Cached input tokens were around 5 % on Codex although the prompt is ordered static-first ([tool-loop.md](tool-loop.md)). To find where consecutive calls first differ, each Codex request logs one line (2026-09-27; `codex_chat_model.prompt_fingerprint`):

```
[codex-cache] key=… purpose=… model=… status=… in=… cached=… instr=<chars>:<1k>/<4k>/<16k> tools=<n>/<chars>:<1k>/<4k>/<16k>
```

— 8-character hashes of the first 1K/4K/16K characters of the instructions and of the tools in send order. The `codex_calls` table has no free-form column, so the log line is the only record; behaviour is unchanged. The cause was never pinned before the move to Claude.

## The Codex spend ledger — who spends the Codex week
