# Trust at the boundary: secrets, taint, approvals

What stops untrusted text from turning into an outward act: the egress secret scan, redaction on the way in, taint tracking, the approval gate (off / shadow / on) and held sends, and the rails on the owner's Chrome. Codex sessions and custom MCP servers have their own containment, in [codex-and-orchestrator.md](codex-and-orchestrator.md).

## Trust at the boundary

(`services/secret_scan.py`, `taint_service.py`, `approvals_service.py`, `routers/approvals.py`; 2026-09-24)
- **Why**: one process reads untrusted inbound text and web pages *and* can send messages as the owner. The tool loop's executor (`graph/tool_loop.py`, one for every path since 2026-10-11) calls `taint_service.check_tool_call` before a tool runs (`graph/tool_loop.py::_boundary_check`, re-exported by `streaming`; it also asks the ping scope, [pings.md](pings.md)) and `note_tool_result` after. A final text that is posted as a reply (a ping's, the Twilio reply) never carries a tool call written as text (`services/tool_markup.py`, [tool-loop.md](tool-loop.md)).
- **Secret scan (always on)**: a credential in an egress argument — messages and `send_message`'s files and an email's `subject`, WhatsApp and mail sends, hosted pages, browser typing and opens (`chrome` and `browser`, by action), the shell's `bash` command, `tell_owner` (a push lands on a lock screen), fetched and looked-at URLs (decoded), search queries, and every string argument, nested ones too, of a custom MCP tool (below). It finds key shapes, JWTs, PEM blocks, OAuth JSON, bare Google OAuth access (`ya29.…`) and refresh (`1//…`) tokens, and exact copies of this process's own key-named environment values, the Codex `auth.json` tokens and the session-signing key (`JWT_SECRET_KEY`, or `backend/.jwt_secret`, which never reaches the environment and has no credential shape: whoever holds it can mint the owner's session; read from the file by `known_secrets` and registered by `auth_service` through `secret_scan.register_known_secret`, 2026-10-12, `tests/test_public_session_key_redaction.py`; defence in depth, since Edward's shell cannot read that file at all, below). A hit answers `Tool error: blocked — the <arg> contains what looks like a secret (<kinds>)` in every mode, chat included, and writes `ledger_events` `egress`/<tool>/`blocked` (kinds only, never the secret). The Twilio reply, sent by the router rather than a tool, goes through `webhooks.scrub_outbound_reply`. `EDWARD_EGRESS_SECRET_SCAN=off` is the emergency switch.
- **His own credentials are not his to read** (2026-10-12 review). Redaction hides a key from the model, but code run in the shell never shows it to the model: a friend's ping that talked the shell into signing a session with backend/.jwt_secret and calling `127.0.0.1:8000` would have acted as the owner, with nothing on the way out for the egress scan to see. So the one exception to open reads is Edward's own credentials, the files `services/computer/rails.py::SECRET_FILES` names (the session-signing key backend/.jwt_secret, the first-password setup code backend/.setup_code, and `.env` at the top and in backend/) in the checkout the backend runs from and in `EDWARD_LIVE_REPO`: the Seatbelt profile denies reading, writing, moving and linking them (`file-read-data`, `file-write*`, `file-link` on each literal; verified through symlinks, relative and `..` paths, case variants, `cp -c` clones and hard links), no directory above them can be renamed (`rails.protected_ancestors`: Seatbelt matches the path at each operation, so `mv ~/code ~/code2` used to carry a checkout and its key out from under the rule), and the editor, `look` and `send_message`'s files refuse them through `rails.can_read`, which compares what is on disk, not the spelling (a case-varied `<repo>/BACKEND/.JWT_SECRET` used to pass the editor's string comparison, and its backup copied the key into `~/edward-home/.trash`); the editor and `look` open files through `rails.open_checked`, which never follows a link swapped in after the check. And the shell may not open TCP to ports 8000 or 3000, or the WhatsApp bridge's 8080, on any address (`rails.denied_ports`), nor reach either of Edward's Postgres clusters (:5432, :5433: the test cluster's superuser trusts the OS user, and its `COPY … TO PROGRAM` would run outside the sandbox), so a borrowed or minted session has nowhere local to go. These, not redaction or the egress scan, are what protect the owner's session; the scan and redaction below stay as defence in depth. A side effect: a script in the live repo that loads `.env` fails when Edward runs it from his shell ([computer.md](computer.md#the-rails); `tests/test_computer_rails.py`, `tests/test_computer_profile_sandbox.py`, `tests/test_computer_editor.py`).
- **…and `.env` is kept out of the backend's start-up environment** (2026-10-12): any process of the same user can read the environment another started with (`KERN_PROCARGS2`, which Seatbelt does not stop), so `backend/start.sh` and `start-graph-worker.sh` stopped sourcing and exporting `.env`; they read only the few settings they need, and the backend loads the file itself once it runs (python-dotenv, the environment winning). Programs the backend starts without an environment of their own (Playwright's driver and browser, the media and EventKit helpers, `sips`, `osascript`) still inherit what it loaded, so leave `JWT_SECRET_KEY` unset (the generated file is read by the backend alone) and read [what the sandbox does not prevent](computer.md#what-the-sandbox-does-not-prevent). `tests/test_start_scripts.py`.
- **These rails stop accidents and a talked-into command, not a determined escape**: the shell runs as the owner's macOS user and can write the rest of the owner's home (shell startup files, `~/Library/LaunchAgents`) and the Homebrew prefix, from which unsandboxed programs run. The full list, and the separate-macOS-user setup for real isolation, are in [computer.md](computer.md#what-the-sandbox-is-and-isnt).
- **A friend's ping doesn't get the owner's machine** (2026-10-12): the shell and the editor, the owner's Chrome, the screens and `look` at the owner's display, Chrome or local files are refused in a friend's ping at the tool boundary (`pings/scope.py::friends_default_refusal`), because the text that drives that turn is someone else's; `EDWARD_FRIENDS_FULL_TOOLSET=on` lifts it ([pings.md](pings.md#the-reply-turn); `tests/test_ping_scope.py`).
- **Redaction on the way in** (2026-10-11; a design decision: the shell may read anything but the credentials above): every `bash` output and every editor `view` passes `secret_scan.redact_secrets` before the model sees it — exact copies of this process's own secrets (`known_secrets`) and anything credential-shaped become `[redacted: <kind>]` — so a key read from disk never reaches the context, and the egress scan above still stands between a command and the network. Neither sees a key that code in the shell uses without printing it, which is why the credentials above are not readable at all (`tests/test_secret_redaction.py`, `tests/test_computer_shell.py`).
- **…and for every local tool's result** (2026-10-11; a security review found that `messages`, `schedule`, `memory`, `look` and the local web results reached the model unredacted although the manual said otherwise): the executor runs `graph/tool_loop.redact_result` on every result before the model, the work rail, the trace and the checkpoint see it — a text result, and the text blocks of a block result; an image or a document block is never touched. The shell's and the editor's own pass stays (a second pass changes nothing); a redaction that breaks withholds the result as a `Tool error:`. It runs on the event loop (a thread would not help: `re` holds the GIL), so every rule is linear on crafted input — the generic `key=value` rule's key-name prefix is bounded (64 chars), the JWT rule is anchored on a non-token character rather than `\b` (a JWT glued to a `-` is not caught), and a new span's overlap is a bisect, not a scan of every span so far: about 0.1–0.2 s per 100K characters of crafted text, ~1.5 s for 16,000 keys in one result, where `-eyJ` × 25,000 took 3 s and the 16,000 keys 10 s before (`tests/test_secret_redaction.py`'s crafted runs). **Not covered: Anthropic's server tools** — `web_search`/`web_fetch` under Claude run at Anthropic and the model reads their results inside the same response, before Edward sees them; only their inputs are scanned, after the fact (`egress`/`detected`, [tool-loop.md](tool-loop.md)). Tests: `tests/test_tool_loop.py::TestSecretsInResults`, `tests/test_secret_redaction.py`.
- **Custom MCP tools are outward** (2026-10-11): the registry tags each tool of a server the owner installed (`metadata.custom_mcp`), and a tagged tool is egress-scanned whole (every string argument), taints the turn with what it returns, is recorded rather than run in a dry run, is journaled as outward, and is refused in a friend's ping — its target can't be checked against the recipient rule — and in any turn whose policy may not reach people ([integrations.md](integrations.md#custom-mcp-servers); `tests/test_custom_mcp_rails.py`).
- **Taint**: `turn_log.tainted` / `taint_reason` — by construction (heartbeat, every mind and pulse pack, Twilio, the `edward-mind` / `edward-surfaces` threads), by a successful read of untrusted content (web, browser, messages, mail — `messages` `mail_search`/`mail_read` —, the owner's calendar and Reminders — `schedule` `calendar`/`reminders`, which hold what others wrote or invited them to —, storage, a custom MCP tool; `taint_service.INGEST_ACTIONS`), or by `history` (a tainted turn in the same thread within 7 days, checked only on a gated send). **A signal only, never a block**: a design decision (2026-10-11) is no new gates on reading, so every turn and surface may read mail and Reminders, and no policy field narrows it (`tests/test_taint_ingest_mail_calendar.py`).
- **The gate — off by default since the toolset (2026-10-11)**: in the shadow weeks on the reference install, 20 of 20 `would_gate` rows were legitimate mind replies, so `on` would have held every reply to a mention. What the gate was for is now deterministic and always on: `send_message`'s recipient rule (the owner asked, the chat this turn was asked in, a chat that addressed Edward in 24 h, or a live conversation — anyone else is the owner's call) and the Chrome rails (below) — [tool-loop.md](tool-loop.md#turnpolicy--what-a-turn-may-do-toolsetpolicypy). Taint marking stays, as a ledger signal. With the variable set, the gate covers a message, mail, hosted page, typing outside a search site (`chrome` `type`/`steps` too), an MCP install, or a Codex session, from a tainted turn whose source is not chat/voice/widget/alexa. `EDWARD_TAINT_APPROVALS` unset or `off` does nothing; `shadow` runs it and logs `taint`/`would_gate`; `on` holds the call in `pending_approvals`, answers `Waiting for <owner>'s approval (#id)`, and pushes Approve/Deny/Open (held in quiet hours; Today shows it as a need; the mind's pack shows it). `POST /api/approvals/{id} {decision}` runs the stored call exactly once (a conditional UPDATE), never bypasses the secret scan, expires after 24 h, is refused while Edward's Chrome tab is on this app, and leaves an `[Approval #id]` note in the thread. A held send is `{"ok": true, "held": true}` in `tools_json` and is not "delivered". **Before turning `on`**: run `shadow` for a week and read `trust` in `/api/health/report` — in `on` mode every heartbeat or mention reply to a third party needs a tap. Since 2026-09-27 the PWA chat keeps its turn across stream steps ([tool-loop.md](tool-loop.md)), so a chat turn that reads untrusted content is tainted and feeds the thread's history taint like every other turn.
- **Twilio answers only the owner** (2026-10-12): a Twilio turn reads like any other (its reads are open) and its final text is texted to the sender, so an answer to anyone let a stranger who found Edward's number ask for the owner's calendar or memories by SMS. After the signature check, `routers/webhooks.py` gives a turn only to a text from the owner's handles (`EDWARD_OWNER_HANDLES` and heartbeat config's `imessage_owner_handles`, compared like the iMessage listener; two numbers that both carry a country code must match on every digit); anyone else's is held with no turn, no reply and no push (ledger `twilio_inbound`/`held`, [integrations.md](integrations.md#messaging-and-the-tool-lists)). `EDWARD_TWILIO_ANSWER_ANYONE=on` answers everyone, with a prompt line saying the sender is not the owner, which is a prompt, not a wall.
- **The mind never texts the owner**: a `mind` or `pulse` turn's send addressed to the owner (`EDWARD_OWNER_NAME`, the owner handles) is refused in `_boundary_check` before the taint gate; `tell_owner` is how Edward reaches them ([mind.md](mind.md)).
- **The household hub's voice is not the owner** (2026-10-11): `/hub/ask` declares `surface: "hub"` and its turns run as `hub_voice`, never `voice` — so a shared panel gets the recipient rule, never-text-the-owner, stand-downs and the Chrome typing rule like any turn the owner is not part of, and no list that means "the owner is speaking" names it (`tests/test_hub_voice_source.py`). Under `EDWARD_TOOLSET=legacy`, where no tool reads the policy, it goes without every send and the shell (`graph/tools.hub_legacy_refusal`). The surface is the page's word, not proven by the server ([voice.md](voice.md)).
- **A held Codex session reads as one** (2026-09-27): the summary is `Codex session in <cwd | a scratch directory>, <can change files | read-only>: "<task…>"` within the 200-character cap; `structured_call` gives Today's `send` as `{channel: "codex", recipient: <where>, text: <the whole task>}`; the push and the Today card ask "Let Edward start Codex?" (`decision_title`) instead of "Approve Edward's send?"; and an approved spawn runs with `wait=False`, so the approval answers "Codex session started …" at once while the session runs as a tracked task (with `wait=True` the POST blocked for the whole session and a tunnel answered 524 after 100 s). Today quotes the whole task under "Codex in <where>" and says "Started Codex" only when the server says so; the Attention room's `HeldSends` shows Start / Don't start. Before this, an approver could read only the first ~150 characters of the task. Latent while the gate is off and the Codex tools are out of the toolset. Tests: frontend `todayModel.test.ts`, `heldSends.test.tsx`.
- **What a Codex session prints is scanned before the turn reads it** (2026-09-27): `cc_manager_service.withhold_secrets` runs the egress scanner over a session's output and error before the task row is written — a finding withholds the text whole (`[Withheld: … (anthropic_key) …]`) and writes `ledger_events` `egress`/`spawn_cc_worker`/`withheld` with the kinds only. Codex's seatbelt allows full-disk reads in every mode, so a task built from a web page could ask it to print `.env`. The environment allowlists for Codex and custom MCP servers keep secrets out of their *environment*, not out of their reach by path ([codex-and-orchestrator.md](codex-and-orchestrator.md)).
- Tests: `tests/test_secret_scan.py`, `test_taint_gate.py`, `test_taint_executor.py`, `test_approvals.py`, `test_trust_wiring.py`; frontend `__tests__/notificationNav.test.ts`, `__tests__/swPush.test.ts` (the service worker carries a copy of `notificationNav`'s helpers; the test pins that they agree).

## Chrome's rails, and the browser that is his own (2026-10-11)

The toolset rebuild ([computer.md](computer.md)) gave Edward two browsers. **The owner's Chrome** (the `chrome` tool, `services/toolset/browsers.py`) is off unless `EDWARD_CHROME_HANDS=on`; off, the extension's socket is refused and the tool answers that Chrome hands are off, touching nothing. On, the socket still takes only a direct loopback connection (no proxy or tunnel header) with the `chrome-extension://` Origin of Edward's own extension, whose ID the manifest's public key fixes (`EDWARD_CHROME_EXTENSION_ID` replaces it), so neither the LAN, the tunnel, a web page nor another installed extension can become Edward's hands ([screen-and-browser.md](screen-and-browser.md#edwards-hands-in-the-owners-chrome)), and three rails are checked before an action runs, in every turn and on every surface:

- **Typing acts as the owner.** `type`, Enter, or `steps` that type, outside a search site (`taint_service.SEARCH_TYPING_HOSTS`) or Edward's own /screen (the hosts of `EDWARD_PUBLIC_BASE_URL`, localhost and this Mac's `.local` name), runs only when the owner is the one asking in this turn — a message typed into Gmail or Slack goes out as them. This is "never start or join other people's conversations unasked", enforced deterministically; under the old path it was the shadow taint gate's `would_gate` on `browser_type`.
- **Clicks that act as the owner** — an element whose label says send, post, reply, publish, delete, remove, accept, decline, confirm, submit, unsubscribe, sign out, transfer, share, invite, RSVP, archive, forward, follow or block (word-bounded, read from the page at click time) — need the owner asking too.
- **Payments are the owner's.** A payment label (place order, buy now, pay, checkout, purchase, confirm payment, add card, …; word-bounded, so "Paywall" passes) or typing a number that passes the Luhn check is refused in every turn, the owner's own included: the owner does those themselves, and Edward says it's ready.

**His own browser** (`browser`, `services/headless_browser.py`) holds none of the owner's logins, opens http(s) only, and never reaches this Mac or the LAN (an SSRF guard on every request, and the final URL checked after every navigation and click because redirect hops are not routed). `web_fetch`'s local fetch and `look`'s URL fetch use the same guard on every hop. The executor's egress secret scan covers these tools' URLs and typed text through the toolset's action-aware table (browser and chrome `open.url` / `type.text` / `steps`, `web_fetch.url`, `look` URLs).
